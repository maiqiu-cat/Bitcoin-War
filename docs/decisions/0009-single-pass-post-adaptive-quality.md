# 0009：单 pass 后期合成、紧凑粒子与自适应画质

- 状态：采用（2026-10-17）
- 取代 [0007](0007-hdr-postprocessing.md) 里的管线描述；0007 的「发光靠提高颜色亮度，不靠降低阈值」原则继续有效。

## 背景

2026-10-17 的特效与性能审查（本机 `~/Documents/CODE_REVIEW_2026-10-17-bitcoin-battle-effects-perf.md`）实测：桌面 1600×900 的 9.8 ms 冻结帧里后期链路占 5.6 ms，平板 / Retina 5.6 MP 的 27.4 ms 里占 20.7 ms（只有 40 fps，GPU 进程 1.35 GB）。原因不是泛光的模糊链（只有 0.3 ms），而是 EffectComposer 的结构：四个全分辨率 pass、三次 MSAA 解析，第二个 4× MSAA 的 HalfFloat 目标只承接一个全屏四边形。另外 9000 个粒子里约 8850 个已死仍按原尺寸绘制，点精灵又受 GPU 的 511 px 上限；手机上没有任何自适应，只有手动 `q=low`，而 `q=low` 的画面因为自定义 shader 缺色调映射而发黑。

## 决定

1. **后期自己组装**，不用 EffectComposer：场景 → HalfFloat（MSAA 可调）→ 泛光链（`UnrealBloomPass` 子类，跳过最后的加法混合，起始分辨率 = CSS 尺寸的一半）→ 一个 Finish 全屏 pass 把泛光、移轴、调色、暗角、ACES 色调映射和 sRGB 一次做完，直接画到画布。两个全分辨率 pass、一次解析。
2. **所有自定义 ShaderMaterial 的片元末尾带 `tonemapping_fragment` 和 `colorspace_fragment`**，后期开关两条路径颜色一致。
3. **粒子改成 billboard 四边形实例，存活压缩**：只上传、只绘制存活区间；世界尺寸 = size × 0.46，与原点精灵的像素大小一致；顶点着色器保证最小像素尺寸。烟雾用一张烘好的平铺 fbm 噪声贴图做轮廓，用屏幕空间梯度和太阳方向算明暗。
4. **单位按高水位槽位绘制和上传**，几何索引化；阴影图隔帧更新，触屏 2048²。
5. **画质分档 1–5 加调节器**（`src/render/quality.ts`）：桌面从 5 起，触屏从 4 起（像素比 ≤ 1.5、MSAA 2×、阴影 2048² 隔帧）；按 rAF 间隔中位数自动降档、缓慢回升，降过两次的档位不再尝试。`q=1..5`/`q=high` 固定档位，`q=low` 保留为最省模式。
6. 几项观感修正同时落地（详见 visual-system.md）：前线脉冲按回合宽度归一化并限频，前线光带调细调暗，庆祝改成胜方基地上空的烟花，冲击环改径向渐变贴图，火球不再染成阵营色，步枪对射从每帧维护的前排静止列表里抽人，震屏改阻尼振荡，竖屏放宽视角并拉远镜头，夜晚泛光阈值提高，天空地平线以下渐暗，湖泊加岸线渐隐和涟漪。

## 后果

- 画面在三套预设下与改造前一致或更干净（前后对比截图在审查探针目录 `impl/shots/`）；`post=0` 和 `q=low` 的画面不再发黑。
- 帧成本和显存下降，数字见 session-log 会话 23；手机和平板默认档位用更低的像素比和 MSAA，清晰度略降，换来可用的帧率。
- 代码里不再有 `EffectComposer`、`RenderPass`、`ShaderPass`、`OutputPass`；`PostFX` 的 `setSamples/setBloom/tiltEnabled` 是档位切换的接口。
- 验证脚本默认 URL 没有 `q`，调节器可能在慢机器上降档，截图随之变化；需要确定性时加 `q=high`。

## 何时重新评估

- 真机实测（backlog「移动端实测」）发现档位阈值或触屏默认档不合适时，调 `qualityFor()` 和调节器参数。
- 单位数再上一个量级时考虑 LOD（ADR 0005）。
- 需要选择性泛光时，改分层渲染。
