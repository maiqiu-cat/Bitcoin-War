## P1：验证缺口和稳定性

- [ ] **观察到实盘 BTC 爆仓**：跑 `pnpm verify:feeds 300`，或者等行情剧烈时跑。核对 Bybit `allLiquidation` 里 `S=Buy` 是否真的表示多头被爆（拿价格方向和 OKX 的 posSide 交叉验证）。核对完更新 `exchanges.md`。
- [ ] **在无地区限制的网络下验证 Binance**：确认它进入指数、偏差正常；forceOrder 能出事件。
- [ ] **盘口校验**：OKX 用 `checksum` 和 `seqId/prevSeqId`，Kraken 用 CRC32 checksum。校验失败就重新订阅。
- [ ] **Bitstamp 冷启动权重偏低**：可以先给一个 24h 成交额的先验值，或者等滚动窗口满了再纳入指数。
- [ ] **模拟行情不确定**：把 `SimFeed` 改成由外部按步驱动，做到逐帧可复现，方便视觉回归测试。
- [ ] **线上音频验收脚本去除时间依赖**：`verify:audio` 的 A/B2/B3 假设资源加载完时模拟行情仍在平静阶段；公网加载较慢时可能已经激战或胜利。固定模拟速度与回合范围，或在检查前强制受控状态。2026-10-02 的线上受控复核已证明当前产品行为正常。

## P1：性能和适配

2026-10-17 做了特效与渲染性能审查（本机 `~/Documents/CODE_REVIEW_2026-10-17-bitcoin-battle-effects-perf.md`，不入库；探针、截图和原始数据在同名 `-probes/` 目录）。实测（本机 GPU）：桌面 1600×900@1 冻结帧 9.8 ms，其中后期链路 5.6 ms；平板/Retina 5.6 MP 为 27.4 ms（40 fps），后期 20.7 ms，GPU 进程显存 1.35 GB。下面按实测收益排序，括号里是桌面 / 手机视口 / 平板预计节省的毫秒；报告第 4 节有分批顺序，第 5 节有验收脚本。

- [ ] **后期链路第二个合成目标去掉 MSAA 和深度**（0.8 / 0.8 / 4.1，画面不变）：`src/render/post.ts` 里 `EffectComposer` 把 4× MSAA 目标 clone 成两个，而 `renderTarget1` 只承接 Finish 的全屏四边形。报告 P-1 第 1 步。
- [ ] **死粒子不再绘制、只上传存活区间**（0.7 / 0.8 / 2.1，最差镜头 2.7～2.9，画面不变）：粒子死亡时 `size` 归零，存活粒子压缩到前面，`setDrawRange` + `addUpdateRange`；`gl_PointSize` 钳到 [2.5, 256]。现在 9000 个粒子里约 8850 个已死仍按原尺寸画，每帧整缓冲上传约 730 KB。报告 P-2。
- [ ] **阴影隔帧更新、触屏用 2048²、`PCFSoftShadowMap` 改 `PCFShadowMap`**（0.5 / 0.5 / 1.1，显存 −96 MB）：three r186 已删除 `PCFSoftShadowMap`，启动时有警告。报告 P-3。
- [ ] **士兵和坦克 InstancedMesh 按高水位设 `count`、改索引几何、`addUpdateRange`**（本机 ≤ 0.3；手机顶点负载约 −45%）：现在每帧按 5000 个槽位画两遍（主 pass + 阴影），3.2 M 次顶点着色器调用，85% 的三角形是空实例。报告 P-5。
- [ ] **泛光链 1/4 分辨率**（0.3 / 0.3 / 1.3，截图逐像素一致）。报告 P-1 第 2 步。
- [ ] **CPU 小项**：`fitReserveLabels` 每帧读 `offsetWidth` 强制布局（0.45 ms/帧，改为缓存标签尺寸）；`groundHeight` 湖泊用平方距离早退；炮弹拖尾按时间而不是按帧发射；`explosion()` 不再每个粒子分配对象；爆炸点光平时 `visible = false`；去掉没有使用者的 `preserveDrawingBuffer: true`（去掉后跑 `verify:screens`）。报告 P-6～P-9、P-12。
- [ ] **自适应画质**：触屏默认 DPR 封顶 1.5、场景 MSAA 2×、阴影 2048²；按帧间隔自动升降档；`q=` 只设初始档。**前提**是先修 `post=0` 下的色调映射（见已知问题），否则降到关后期时画面像坏了。报告 P-10。
- [ ] **泛光合成 + Finish + 输出合并成一个 pass 直出屏幕，DPR ≥ 2 时场景 MSAA 2×**（估算桌面 −2～3，平板 −8～12）：这是 Retina 和平板回到 60 fps 的那一步。报告 P-1 第 3、4 步。
- [ ] **移动端实测**：布局已修（会话 11，`verify:mobile` 24/24）；上面各项做完后在 iPhone Safari、Android Chrome 真机上看 `__bb.stats.fps`、触控和发热。本机把 CPU 降速 4.8 倍，手机视口仍 60 fps，瓶颈在 GPU 填充。
- [ ] **竖屏镜头取景**：手机竖屏的水平视角只有约 25°，只看得到战场中段，两端基地常在屏幕外。按宽高比放大竖屏视角或拉远镜头（报告 V-14）。
- [ ] **CSS2D 飘字改成对象池**：现在每次都新建 DOM 节点。
- 降级到 P2：**远处单位 LOD**（先做高水位 `count`，真机测出顶点瓶颈再做）；**价格刻度实例化**（≤ 0.2 ms）；**页面不可见时降频**（浏览器本来就停 rAF，回到前台时 `dt` 已封顶 0.05）。
- 不要做：为性能简化地面 shader 的 5 次噪声（上限 0.3～1.5 ms）；靠降低泛光强度省时间（贵的是合成方式，不是模糊链）。

## 已知问题（目前可接受）

| 问题 | 影响 | 位置 |
| --- | --- | --- |
| 关掉后期（`post=0`、`q=low`）时，天空发黑、烟雾全黑 | 只出现在低配模式；做自适应画质之前必须修（2026-10-17 审查 V-10） | ADR 0007；`lighting.ts`、`effects.ts` 的 ShaderMaterial |
| 窄回合（如 `range=0.06`）下，储备标签显示的兵数很大（上万） | 只是显示 | `world.setLayout` |
| 阵亡单位会在原地躺 2 秒，然后消失 | 设计如此 | `units.ts` |
| 截图验证的 FPS 会受同时打开的浏览器标签页影响 | 测量误差 | `verify:screens` |
| 首个回合要等指数出来，约 1–2 秒，期间场上为空 | 体验 | `main.ts` |
| HUD 是手写 DOM，状态同步靠 `applyLang()` 等手动调用 | 维护成本 | ADR 0001 |
